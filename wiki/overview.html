總覽：校園網站 GEO（以政大國際招生為例）

主題定義

生成式引擎優化（GEO，Generative Engine Optimization） 是針對生成式搜尋引擎（如 Google AI Overviews、Bing Copilot、Perplexity.ai）優化網頁內容能見度的新興範式。不同於傳統 SEO 追求關鍵字排名，GEO 關注內容在生成式回應中被引用的長度、位置、可信度與主觀印象。

核心來源

  • S1：Aggarwal et al., “GEO: Generative Engine Optimization”, arXiv 2311.09735 v3 (KDD 2024) — 奠基性學術工作，定義 GEO 框架、GEO-bench 基準、9 種優化方法、兩大能見度指標，並實證 top-3 方法可提升 30-40% 能見度。
  • S2：Google, “Optimizing your website for generative AI features on Google Search” — 平台官方指引，說明 AI 摘要運作（RAG、query fan-out）、SEO 重構、內容策略、迷思破除（llms.txt、切塊、結構化資料）、效能測量與代理型體驗。
  • S3：Google, “AI features and your website” — 解釋 AI Overviews/AI Mode 運作（query fan-out）、顯示資格（需被索引且符合片段資格）、SEO 最佳實踐仍適用無額外要求、robots.txt 控制、點擊品質較高。
  • S4：Google, “Intro to How Structured Data Markup Works” — schema.org 結構化資料技術規範，說明 JSON-LD、Microdata、RDFa 格式、一般指引、驗證工具與案例研究。
  • S5：Google Search Central, “Latest Google Search documentation updates” — 官方文件更新記錄，記錄 FAQPage/HowTo 複合式結果政策變更（2023-08、2026-05）、llms.txt 澄清（2026-06-15）、Google-Extended（2023-09-28）、preferred sources 推出（2026-05-27）、AI 優化指南新增（2026-05-15）等。
  • S6：llms.txt proposal (llmstxt.org) — 新興提案標準，不可視為已生效網路標準。
  • S7：OpenAI, “Crawlers documentation” — AI 爬蟲用途與控制說明。
  • S8：政大國際招生網站 GEO 策略／提案（學生前期研究，非正式出版） — 提供政大招生情境的基準測試數據、網站規格、衡量指標、多語言規劃與對齊既有計畫文件的具體細節。
  • S9：Perplexity, “Perplexity Crawlers” — Perplexity 官方文件，說明 PerplexityBot、Perplexity-User 兩種代理的用途、User-Agent、IP 範圍 JSON、robots.txt 行為與 WAF 設定指引。
  • S10：Google, “Tell Google about localized versions of your page” — 國際化 SEO 官方文件，說明 hreflang 三種實作方式、雙向連結強制要求、x-default 回退值、語言/地區代碼標準（ISO 639-1、ISO 3166-1 Alpha 2、ISO 15924）。

關鍵發現（來自 S1）

  1. GEO ≠ SEO：關鍵字堆砌在生成式引擎無效（verbatim 待查）；高效方法為 Cite Sources、Quotation Addition、Statistics Addition [S1]。
  2. 指標體系：Position-Adjusted Word Count（位置調整字數）與 Subjective Impression（主觀印象，七面向經 G-Eval 正規化）[S1]。
  3. 民主化潛力：低排名網站受益大（第 5 名 +115.1%），高排名網站可能被擠下（第 1 名 -30.3%）[S1]。
  4. 領域相依：同一方法在不同領域效果差異大，需領域適配 [S1]。
  5. 組合更強：Fluency Optimization + Statistics Addition 最佳；Cite Sources 結合其他方法平均 +31.4% [S1]。
  6. 真實環境驗證：Perplexity.ai 上 Quotation Addition +22% PAWC、Statistics Addition +37% SI [S1]。

Google 官方指引關鍵點（來自 S2、S3、S4、S5、S10）

  1. SEO 最佳實踐仍適用：生成式 AI 功能建立在核心排名系統之上，既有 SEO 最佳實踐持續相關 [S2][S3]。
  2. RAG 與查詢擴展：生成式回應依賴檢索增強生成（RAG/grounding）與查詢擴展從索引取得內容 [S2]。
  3. Query fan-out：AI Overviews 與 AI Mode 使用 query fan-out 技術拆解子查詢以發展回應 [S3]。
  4. AEO/GEO 仍屬 SEO：從 Google 搜尋角度看，優化生成式 AI 搜尋即優化搜尋體驗，因此仍屬 SEO [S2]。
  5. 無需 llms.txt：Google 搜尋忽略 llms.txt 等專用機器可讀檔案 [S2][S5]。
  6. 無需為 AI 切塊或改寫：Google 系統理解同義詞與語意 [S2]。
  7. 結構化資料非必要：但建議保留作為整體 SEO 策略一環 [S2][S3]。
  8. 結構化資料技術規範（S4）：Google 建議使用 JSON-LD，最易實作維護且可動態注入；必須描述使用者可見內容，不得標記隱藏資訊；需遵循一般指引與類型專屬指引；可用 Rich Results Test 驗證、Search Console 監控 [S4]。
  9. 優先非大眾化、專家、以人為本內容：獨特視角、超越常識、結構清晰、輔以圖影片 [S2]。
  10. 技術基礎：可索引、可爬取、HTML 文字呈現關鍵資訊、語意化 HTML、良好頁面體驗 [S2][S3]。
  11. 顯示資格：頁面必須先被索引且合乎 Google 搜尋片段顯示資格，才能出現在 AI 功能中 [S3]。
  12. robots.txt 控制：robots.txt 指令控制 Googlebot 爬取是網站擁有者管理搜尋存取的方式 [S3]。
  13. 效能測量：Search Console 生成式 AI 效能報告（Web search type）[S2][S3]。
  14. 點擊品質：來自 AI Overviews 的點擊品質較高，使用者較可能在網站停留更久 [S3]。
  15. 代理型體驗：瀏覽器代理、UCP 協定為新興趨勢 [S2]。
  16. FAQPage/HowTo 複合式結果政策演進（S5）：
    • 2023-08 部落格宣佈 HowTo 棄用、FAQ 僅限政府/醫療權威網站 [S5]。
    • 2023-09 文件移除 HowTo 文件、更新 FAQ 文件說明 [S5]。
    • 2026-05-07 起 FAQ 複合式結果不再顯示，2026-05-08 發布棄用通知，2026-06-15 移除 FAQ 文件 [S5]。
    • S8 曾把保留 FAQPage 寫成「僅為讓 AI 解析問答結構」；S2/S3 並未證明 FAQPage 能提升生成式 AI 的解析或引用，因此不把它列成 GEO 必要作法 [S5][S8][S2][S3]。
  17. Google-Extended（S3、S5）：2023-09-28 新增權杖，供網站管理內容是否用於 Bard／Vertex AI 等生成式 API 的改進 [S5]。S5 於 2024-02-08 補充：「Google-Extended doesn’t affect Google Search」[S5]。S3 將 Googlebot（搜尋，含 AI 功能）與 Google-Extended（其他系統的訓練與 grounding）分開 [S3]。不應把它當成 AI Overviews 或 Google 搜尋的索引開關。
  18. Preferred sources（S5）：2026-05-27 起向 AI Overviews/AI Mode 推出，資格條件待查 [S5]。
  19. AI 優化指南新增（S5）：2026-05-15 新增，含非大眾化內容、AEO/GEO 迷思破除、AI 代理初步指引 [S5]。
  20. 國際化多語言導向（S10）：
    • 三種等效方法：HTML link 標籤、HTTP Header、XML Sitemap，三選一即可 [S10]。
    • 每個語言版本必須列出自身與所有其他版本，且需雙向連結，否則標記被忽略 [S10]。
    • 替代網址必須為完整合格網址（含 http/https）[S10]。
    • 保留值 x-default 用於無符合語言/地區時的回退頁面，建議用於語言選擇頁 [S10]。
    • 語言代碼需符合 ISO 639-1，地區代碼需符合 ISO 3166-1 Alpha 2，腳本代碼可用 ISO 15924 [S10]。
    • Google 不使用 hreflang 或 HTML lang 屬性偵測頁面語言，而是演算法判斷（verbatim 待查）[S10]。
    • 常見錯誤：缺少回連結、語言/地區代碼錯誤 [S10]。

llms.txt 提案關鍵點（來自 S6）

  1. 提案而非標準：llms.txt 為社群提案（v2 於 2026 年 8 月發布），非 IETF/W3C 正式標準，Google 搜尋明確忽略 [S6][S2][S5]。
  2. 格式規範：H1 專案名稱（必要）、blockquote 簡短摘要、可選細節、H2 分組的檔案清單（含超連結與可選備註）[S6]。
  3. v2 新增可發現性機制：rel="alternate" type="text/markdown" 指向頁面 Markdown 版本，rel="describedby" 指向涵蓋該頁的 llms.txt；允許兩種 Markdown URL 形式（page.html.md 或 page.md）[S6]。
  4. 採用現象：數千網站發布、文件平台自動生成、Chrome Lighthouse 納入稽核、AI 實驗室自家文件發布 [S6]。
  5. 與現有標準共存：與 robots.txt、sitemap.xml 用途不同，互補不取代 [S6]。
  6. 政大部署：S8 採用提案格式但誠實標註非必要、非標準、成本低可放 [S8]。

OpenAI 爬蟲控制關鍵點（來自 S7）

  1. 四種獨立爬蟲/用戶代理：OAI-SearchBot（搜尋檢索）、OAI-AdsBot（廣告驗證）、GPTBot（模型訓練）、ChatGPT-User（用戶即時請求）[S7]。
  2. 搜尋與訓練獨立控制：OAI-SearchBot 控制 ChatGPT 搜尋結果顯示，GPTBot 控制模型訓練使用，兩者可分別設定 [S7]。
  3. 合併爬取可能：若同時開放 OAI-SearchBot 與 GPTBot，OpenAI 可能合併爬取避免重複 [S7]。
  4. ChatGPT-User 非自動爬取：由用戶動作觸發，robots.txt 規則可能不適用 [S7]。
  5. IP 範圍 JSON 驗證：各爬蟲發布 IP 範圍 JSON（searchbot.json、gptbot.json、adsbot.json、chatgpt-user.json）供防火牆白名單驗證 [S7]。
  6. robots.txt 約 24 小時生效：OpenAI 系統約需 24 小時調整 [S7]。

Perplexity 爬蟲控制關鍵點（來自 S9）

  1. 兩種獨立代理：PerplexityBot（搜尋索引）、Perplexity-User（用戶即時請求）[S9]。
  2. 用途區分：PerplexityBot 用於搜尋結果呈現與連結，不作為 AI 基礎模型訓練爬蟲；Perplexity-User 支援用戶動作，非自動爬取 [S9]。
  3. robots.txt 行為差異：PerplexityBot 建議在 robots.txt 允許；Perplexity-User 一般忽略 robots.txt 規則 [S9]。
  4. IP 範圍 JSON 驗證：兩種代理皆發布 IP 範圍 JSON（perplexitybot.json、perplexity-user.json）供防火牆白名單驗證 [S9]。
  5. WAF 設定指引：提供 Cloudflare WAF 與 AWS WAF 具體配置步驟，建議結合 User-Agent 比對與 IP 範圍驗證 [S9]。

政大國際招生網站的實測基準線（來自 S8 學生前期研究）

  • 基準測試日期：2026-11-12，約 19:20–19:40（台北時間）[S8]。
  • 方法：WebSearch 工具（搜尋結果 + AI 自動摘要）作為替代指標，非 ChatGPT、非 Google AI 摘要、非 Perplexity.ai；單一時間點快照 [S8]。
  • 結果：10 題中政大出現在 AI 摘要答案 5 題（B2、B5、B6、B9 明確推薦，B10 次要提及）、僅來源 1 題（B8）、完全缺席 4 題（B1、B3、B4、B7）[S8]。
  • 關鍵洞察：政大在精準利基問題（台灣研究、兩岸研究、英語 MBA、日本研究）有出現；在廣泛選校問題（東亞讀國際關係、台灣適合國際生、台灣英語授課碩士、台灣學漢學）完全缺席，答案由台大、師大、清大、陽明交大、成大主導 [S8]。
  • 強項分散：IMPIS、IMAS、IMBA、國關中心、華語中心、日本研究學位學程等官網資訊存在，但散落各系所，缺乏 AI 易引用的整合入口 [S8]。

對政大國際招生網站的啟示（推論）

  • 優先動作：在關鍵招生頁面導入「引用官方來源」、「學生/教授真實引語」、「關鍵指標量化」[S1][S8]。
  • 風格優化：提升可讀性、流暢度、結構化呈現（問答體、40–60 字直接答案）[S1][S8]。
  • 長尾頁面優先：系所專頁、獎學金、生活資訊等低排名頁面潛在獲益最大 [S1][S8]。
  • 避免舊習慣：停止關鍵字堆砌，轉向內容可信度與呈現品質 [S1][S8]。
  • 因應 query fan-out：每頁涵蓋主問題與相關子問題，增加被多個子查詢檢索到的機會 [S3][S8]。
  • 技術規格落地：JSON-LD（FAQPage、EducationalOccupationalProgram 等）、robots.txt 開放 AI 爬蟲、hreflang 多語、llms.txt 索引、sitemap.xml [S8][S10]。
  • 結構化資料部署：依 S4 規範採用 JSON-LD，內容與可見文字一致，經 Rich Results Test 驗證、Search Console 監控 [S4][S8]。
  • FAQPage 策略調整：FAQ 複合式結果已於 2026-05-07 起不再顯示，說明文件於 2026-06-15 移除 [S5]。現有官方來源不足以證明保留 FAQPage 能增加生成式 AI 的解析或引用，故不列為 GEO 必要項目；S8 原型若仍放置 FAQPage，應視為與可見問答一致的標記，而不是已證實的 AI 效果 [S5][S8][S2][S3]。
  • llms.txt 部署：低成本放置但非核心策略，誠實標註 Google 忽略 [S5][S8]。
  • 監測與驗證：每月重跑基準 10 題、GA4 建立 AI Referral 管道、Search Console 追蹤目標問題趨勢、每季檢查第三方引用 [S8]。
  • 分期建置：原型（P1 三語）→ 內容轉換（P2 + ko/vi/id）→ 上線優化（3 個月基準追蹤）→ 擴充（百年校慶、第三方引用）[S8]。
  • 資料查核機制：國合處指定窗口每學期確認招生時程、學程清單、獎學金、人數統計；上線前統一數字落差 [S8]。
  • 平台差異策略：針對 Google 搜尋遵循 S2/S3 以既有 SEO 為基礎；針對其他 GE 參考 S1 方法論適配（推論，基於 S1、S2、S3 定義張力）[S1][S2][S3]。
  • OpenAI 爬蟲策略：允許 OAI-SearchBot 讓招生內容出現在 ChatGPT 搜尋，視政策決定是否允許 GPTBot 訓練使用，確保基礎設施放行 ChatGPT-User IP 範圍（推論，基於 S7、S8）[S7][S8]。
  • Perplexity 爬蟲策略：允許 PerplexityBot 讓招生內容出現在 Perplexity 搜尋，確保基礎設施（CDN/WAF）放行 Perplexity-User IP 範圍以支援用戶即時請求（推論，基於 S9、S8）[S9][S8]。
  • hreflang 部署策略：採用 HTML link 標籤法（或 Sitemap 法），每語言版本列出自身與所有其他版本，確保雙向連結完整；代碼遵循 ISO 639-1、ISO 3166-1 Alpha 2、ISO 15924；首頁與語言選擇頁設定 x-default；CMS 自動化產生避免人工疏漏（推論，基於 S10、S8）[S10][S8]。
